# AX.25 over M17 packet mode

A KISS host — BPQ, `kissattach` through `kissnetd`, or anything else that speaks
KISS — connects to the station on TCP port 8001. The station transmits whatever
it is given as M17 packets, and hands back whatever its receiver decodes.

The reflector/IP side of the station is described separately in
[m17-ip-framing.md](m17-ip-framing.md) - that is what the `_net` routines are for.

Packet mode is **off unless `data on` is in `config.txt`**. With it off no
socket is opened, the receive hook returns immediately and the voice path is
exactly as it was.

## Path of a transmission

    BPQ ──KISS/TCP──► kiss.c decoder ──► m17_bridge queue
                                              │
                            m17_ax25_service()│  (bottom of the receive loop)
                                              ▼
                        radio_transmit → carrier → preamble → LSF
                        → 25-byte packet frames → EOT → radio_receive
                                              │
    BPQ ◄──KISS/TCP── kiss_encode ◄── valid_packet_received ◄── receiver

The packet is built and reassembled by `m17_packet.c`, which is the same code
that has the golden-vector tests in [G4GUO/m17-ax25](https://github.com/G4GUO/m17-ax25).
Those three files (`kiss.c`, `m17_packet.c`, `m17_bridge.c`) are copied in
verbatim; `m17_ax25.cpp` is only the glue.

## Commands

| Command | |
|---|---|
| `data` | state and counters |
| `data on` / `data off` | packet mode; remembered in `config.txt` |
| `loopback on` / `loopback off` | build the packet and feed it straight back instead of transmitting (runtime only) |
| `kissport N` | KISS listening port, default 8001 (runtime only) |

`loopback` and `kissport` are not persisted because `config.txt` is rewritten
line by line: the `data on|off` line is replaced by a prefix match, which would
also delete a `data loopback …` line on every toggle.

## On the air

* **LSF**: broadcast destination (`FF FF FF FF FF FF`), source = the station
  `sa`, **stream mode** (P/S = 1), CAN 0, no encryption, META = `AX25` then
  zeros. The META tag is what marks the burst as ours.
* **Framing**: `A5 25 <len hi> <len lo> <AX.25 frame> <CRC hi> <CRC lo>`, the
  CRC covering the four header bytes and the frame, split into 16-byte stream
  frames. KISS carries frames without their FCS, so none is added or stripped.
* **Repetition**: the block is sent at least twice and the burst ends with three
  frames of zeros, which flush the receive-side Viterbi decoder's trellis.
* **Why stream and not packet mode**: packet mode needs a single link setup
  frame to survive, and on this link the last 24 symbols of every frame are
  lost, so its CRC never checks. Stream mode carries the LSF five bytes at a
  time across six frames and repeats it, with rate-1/2 convolutional coding and
  interleaving on the payload — the properties that let a voice over work here.
  The cost is throughput and interoperability: this talks to our own stations,
  not to a third-party M17 packet implementation.  The measurements behind that
  choice, and what they suggest for the specification, are in
  [m17-rx-observations.md](m17-rx-observations.md).
* **Size**: 823 bytes of application data maximum; BPQ's `PACLEN` should be 256
  or less so a single burst stays under 600 ms.

## Channel access

* Channel busy = any M17 frame heard in the last 100 ms (voice or packet), from
  `m17_rx_parse()`.
* After the channel goes quiet, a **3 s quiet period** must pass — this keeps
  bursts out of the gaps between overs in someone else's QSO.
* Then a random 0–3 slots of 40 ms (one M17 frame each), re-drawn if the
  channel goes busy again.
* One frame outstanding, immutable once queued; a frame identical to one
  already queued is dropped, so a host retransmission does not become a second
  burst.
* 20 ms guard after our own EOT before the channel is trusted again.
* A burst in flight is never interrupted: the operator keying the microphone
  waits for it to finish (0.6 s for a 256-byte frame).

## Limitations

* **One KISS host at a time.** A second connection closes the first. Run one
  BPQ instance per station; a second one on the same radio will flap the port.
* DCD is sync-based, not RSSI-based, so a very weak signal that cannot be
  demodulated does not hold the channel off.
* No TX-complete or DCD signalling to the host: KISS has none, and BPQ's `T1`
  therefore starts when the frame is handed over. `FRACK=5000` is a sensible
  value.
* The BPQ instances on `pi-ai-sdr` are hand-started, not systemd units.

## Setting up a second station (Pi 4 + Pluto)

    sudo apt install libiio-dev libasound2-dev libpulse-dev libgpiod-dev \
                     libasound2-plugin-bluez bluez-alsa-utils
    git clone https://github.com/G4GUO/m17_webapp_fargan.git
    cd m17_webapp_fargan/m17gismo
    git checkout feature/ax25-packet
    make -j4 CODEC2_BACKEND=mod NEURAL=1      # no external codec2 needed

`config.txt` in the working directory needs at least:

    sa g4guo-2          # different SSID from the other station
    mode radio
    data on

and BPQ (or whatever host) needs a port like:

    PORT
     PORTNUM=1
     ID=M17 packet
     TYPE=ASYNC
     PROTOCOL=KISS
     IPADDR=127.0.0.1
     TCPPORT=8001
     FRACK=5000
     RESPTIME=3000
     RETRIES=10
     MAXFRAME=1
     PACLEN=256
     KISSOPTIONS=NOPARAMS
    ENDPORT

Do not set `KISSOPTIONS=ACKMODE`: that expects a per-frame acknowledgement the
station does not send.

## Running it unattended

`m17web.service` already exists on `pi-ai-sdr`. BPQ is a templated unit so a
second instance is one command:

    /etc/systemd/system/bpq@.service

    [Unit]
    Description=LinBPQ node %i
    After=network-online.target
    Wants=network-online.target

    [Service]
    Type=simple
    User=charles
    Group=charles
    WorkingDirectory=/home/charles/bpq/%i
    ExecStart=/home/charles/bpq/bin/linbpq
    Restart=always
    RestartSec=5

    [Install]
    WantedBy=multi-user.target

    sudo systemctl enable --now bpq@a

Only one BPQ may connect to a radio at a time (see Limitations), so `bpq@b`
must be pointed at a different port — the station closes the older connection
when a second one arrives, and two hosts pointed at 8001 flap the port.

## When it does not work

`journalctl -u m17web -f` shows one line per event:

    m17web: AX.25 packet mode on, KISS port 8001
    m17web: AX.25 KISS host connected
    m17web: AX.25 transmit 15 bytes          # a burst went out
    m17web: AX.25 receive 15 bytes           # a packet came in from the air
    m17web: AX.25 loopback 15 bytes          # loopback is on: nothing went out

* No `KISS host connected` — the host is not reaching 8001; check `ss -ltn`.
* `transmit` repeating every 5 s with no `receive` — that is SABM retrying
  because nothing answered, which is correct with no peer station.
* `data` answers `Invalid command` — the binary predates this work; check that
  `~/m17web-build` was rebuilt from the branch.

## Open item: transmit envelope ramp

Not done, deliberately — revisit another day.

A burst is audible as a **click at each end** on an ordinary receiver.  The
modulator is constant envelope: it writes `cos(phase)`/`sin(phase)` at full
scale for every sample, so keying into the preamble and dropping the carrier
after the last frame are step changes in amplitude, not ramps.  The click is the
step, plus splatter either side of the signal.

This is *not* sample loss.  The transmit path accumulates into 1920-sample
blocks and then whole 40 ms chunks, and the burst now reports
`AX.25 transmit lost N sample buffers` if a chunk is ever refused; on air it
reports none, so the DAC is receiving every sample.  Zero samples are written
before the preamble (5 ms) and after the last frame (20 ms) so the carrier
starts and finishes at zero, which cleans up the tail but does not remove the
onset step.

The fix is a raised-cosine amplitude ramp over 2–5 ms at each end, and there are
two places to put it:

* **`m17_modulate.cpp`** — correct for every transmission, but shared with the
  voice path, so it changes behaviour that currently works and is used for
  speech.
* **`send_packet()` in `m17_ax25.cpp`** — ramp the first and last few
  milliseconds of this path's own samples.  Contained, no risk to voice, but it
  has to be done on the IQ after modulation rather than on the symbols.

The second is the safer starting point.  Reduce the leading silence to ~2 ms
when the ramp goes in, so the ramp has a defined zero to rise from.
